# Branch 4 website review

This worktree intentionally depends on **unmerged website Branch 3 PR #29**, `origin/feat/homepage-management` at `f81448ee14cc7111437ef9574380898588b30200`. Backend/dashboard Branch 3 are merged; their recorded deployment does not imply this website is deployed. Merge/rebase strategy needs review after PR #29 is accepted. No commit, push, merge or deployment was performed.

Catalogue browsing stays anonymous. Public content and episode records now advertise `playback_available` while retaining nullable `streaming_link`; protected URLs come only from authenticated `POST /api/content/{id}/playback/` with optional `episode` or `miniseries`. Requests use account-bound viewer credentials. Processing/unavailable responses explain the state and offer retry; processing polls are bounded. HLS grants renew before expiry without changing their URL. Delivery configuration must permit credentialed requests and use the shared-domain CloudFront cookies described in backend documentation.

The existing player keeps native HLS when supported, otherwise lazily loads pinned hls.js 1.6.15. Native video controls/fullscreen remain; hls.js offers Auto and manual rendition selection. Controls remain compact, Cinema Mode stays in the existing options menu, and keyboard shortcuts apply when the video is focused. Startup/buffering has a 20-second limit, transient network/media recovery is bounded, and autoplay failure displays Play. Listeners, timers and HLS instances are destroyed on source/account changes. YouTube trailers use supported `onStateChange`, `onAutoplayBlocked` and `onError` events, plus an explicit Retry/fallback link.

Opening detail plays a trailer first after auth/progress restoration where autoplay permits, then authorizes main playback automatically. Resume/explicit playback intent skips unnecessary trailer replay. Episode/part selection is retained in sign-in return destinations. Both password and Google login reuse the existing verified identity backend. Client fixes prevent old profile/refresh/login responses from overwriting a newly selected account; transient refresh failures no longer erase valid credentials. Google ID tokens are still verified server-side; arbitrary email is not authentication.

Configure `NEXT_PUBLIC_API_BASE_URL`, `NEXT_PUBLIC_GOOGLE_CLIENT_ID` and matching backend `GOOGLE_OAUTH_CLIENT_IDS` (exact comma-separated OAuth client allowlist). In Google Cloud configure each real website/staging/localhost JavaScript origin, including scheme/port, on its Web OAuth client. Use separate staging IDs where appropriate. Authorized redirect URIs are only needed for flows that actually redirect; the GIS credential callback here posts an ID token. HTTPS/secure contexts, CSP, popup/iframe policies, certificate trust and consent-screen/test-user restrictions must be checked using actual deployed origins. No client secret belongs in the browser. Existing privileged-account and explicit password-backed Google-link restrictions remain enforced by the backend.

Progress writes stay ordered/throttled (15 seconds) and flush latest valid samples on pause/end/hidden/pagehide/cleanup. Pagehide is best effort: Axios cannot guarantee delivery after tab termination. Per-account/per-selection writers prevent cross-account updates. Backend additive part history supports resuming older episodes while retaining Branch 3's last-viewed snapshot and legacy fallback.

`cbmtv:playback-metric` events expose only finite numeric startup duration, rebuffer duration, quality and error fields; they contain no URLs/tokens/identities. No external analytics service is introduced. Use `node tests/playback-media.browser.mjs` after building with `NEXT_PUBLIC_API_BASE_URL=http://127.0.0.1:18041` for real local generated-media Chrome proof (FFmpeg and Chrome required). This fixture API is local and does not verify Google/AWS. Native capability is suppressed only in the explicitly labeled hls.js phase to exercise actual MSE decoding/quality switching. Screenshots and measured results are in `.next/playback-media-proof/`; copy them before rebuilding.

Tests: `pnpm test`, `pnpm lint`, `pnpm exec tsc --noEmit`, `pnpm build`. On this managed Windows host, the build requires system TLS trust: `NODE_USE_SYSTEM_CA=1` and `NEXT_TURBOPACK_EXPERIMENTAL_USE_SYSTEM_TLS_CERTS=1`. Do not disable TLS verification. Baseline lint warnings remain in unrelated components. Final counts/measurements are in the workspace review.

Staging must exercise real CloudFront child playlists/segments/expiry, Google consent/origins/linking/account switching, long sessions, autoplay-blocked Safari/iOS/Android, range fallback, throttled networks, big/interrupted uploads and existing mobile clients. Synthetic SDK events are not real-device validation. Existing adverts remain unchanged; ad scheduling/Branch 6 integration is a later dependency, with no ad platform added here.

Rollback requires coordinated frontend/backend artifacts. Older clients consume public `streaming_link` directly and need the new authorization contract before backend redaction is released. Do not restore public protected media merely to accommodate an old client. Preserve additive database records and private objects throughout rollback.
